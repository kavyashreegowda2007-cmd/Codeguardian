### What the Frontend Currently Does

`frontend/src/main.tsx` is a **single-file, single-screen** React app (`App` component):

1. **Change request + repo path inputs** — two text inputs rendered inline
2. **Analyze button** — POSTs to `/api/analyze`, stores result in component state and `localStorage`
3. **Pipeline progress bar** — 5 hardcoded step labels, all marked done once a result exists
4. **Impact map** — a horizontal flow diagram with 5 static node types (Change Request, Code Impact, API Surfaces, Database, Test Impact) using div-based layout, no D3
5. **Security findings panel** — renders `security_risks[]` from analysis result
6. **Implementation plan list** — renders `plan[]` tasks with file pills and risk tags
7. **Approve manifest / Generate & Implement buttons** — call `/api/implement`
8. **Verification section** — calls `/api/verify`, renders test counts
9. **Final report section** — static grid from analysis + verification data
10. **Session restore** — reads `codeguardian.analysisId` from localStorage on mount

CSS split across four files: `styles.css`, `approval.css`, `report.css`, `verification.css`.

**Current visual theme:** light parchment/cream (`#f2f0e9` background), olive/green accents, `Manrope` + `DM Mono` fonts. **Not** the dark developer theme the master prompt requires.

### Storage Layer (SQLite via `backend/storage.py`)

Single table:

```sql
CREATE TABLE IF NOT EXISTS analyses (
    analysis_id TEXT PRIMARY KEY,
    repository_path TEXT NOT NULL,
    request TEXT NOT NULL,
    created_at TEXT NOT NULL,
    record_json TEXT NOT NULL   -- full JSON blob of the analysis record
)
```

The entire record (including nested `result`, `verification`, `implementation`, `status`, optional `temp_clone_dir`) is stored as a single JSON blob in `record_json`. There is no separate findings table, graph table, or job queue.

Database path defaults to `.codeguardian/analyses.sqlite3`; overridable via `CODEGUARDIAN_DB_PATH`.

### What the Existing Analyzer Does (`analyzer/repository.py`)

`scan_repository(root)` walks the repository and produces a `RepositoryEvidence` object:
- **Files** — all files with supported extensions (`.py .js .jsx .ts .tsx .json .sql .md .txt .toml .yaml .yml`)
- **Symbols** — Python AST parse: functions, async functions, classes, with file + line
- **Imports** — Python AST import resolution, including relative imports mapped to repo files
- **Routes** — Python FastAPI decorator detection (`@router.get/post/...`) with prefix resolution; basic regex for JS `router.get(...)` etc.
- **Dependencies** — parsed from `requirements.txt`, `pyproject.toml`, `Pipfile`, `package.json`, `package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`
- **Tests** — file-level discovery (`test_*.py`, `*_test.py`, `*.test.ts` etc.)
- **Database components** — files with `.sql` extension or "model"/"database" in name
- **Configuration** — files starting with `.env` or containing "config" in name
- **Security findings** — regex patterns: plain-text credential comparisons, `eval`/`exec`/`shell=True`, sensitive values in logs

`analyze_change(root, request)` builds an `ImpactResult`:
- Term matching against request words, expanded via import relationships
- Confidence score (heuristic, 35–98%)
- Five-step implementation plan grouped by: implementation files, persistence/config, dependencies, tests, verification

**What it does NOT do:** function-level dependency graphs, cross-file call graphs, line-level change tracking, async job processing, graph serialization for D3 rendering.

#### Enhanced Findings Schema
The current `security_risks: list[str]` is a flat string list. The new findings model adds:
- Per-finding severity level (critical / high / medium / low / info)
- Category (security / dependency / test-coverage / api-risk / database / code-quality)
- File path + line references
- Source tag: `deterministic` (from analyzer regex) vs `ai-hypothesis` (from Nebius)
- Confidence score + reasoning
- Recommended action text

Existing `security_risks` data will be mapped to the new schema on the graph/findings endpoints to maintain backward compatibility.
